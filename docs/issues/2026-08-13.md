# 2026 年 8 月 13 日：墨水屏不刷新（画面永远停留在旧黄历）

## 现象

1. 屏幕一直停留在旧的黄历画面：开关机、甚至刷入其他固件都不变化。
2. 配网模式不显示二维码，但 192.168.4.1 配网页可正常访问；配网保存后也不进入默认界面。

## 根因

墨水屏（E Ink Spectra 6，ED2208 控制器）是双稳态的，断电后画面保留，这是正常特性；真正的问题是**面板不再执行任何刷新**（冷启动的全白清屏、配网二维码、黄历渲染全部无效）。

链路：

1. `enterHomeDeepSleep()` 在进入深度睡眠前调用 `M5.Display.sleep()`，向 ED2208 发送 `DEEP_SLEEP`（0x07 0xA5）命令；PM1 常供电，面板一直保持通电并停留在深睡状态。
2. 唤醒后 M5GFX 对 PaperColor 的首轮初始化不带硬件复位（`_pin_reset(12, use_reset=false)`，`Panel_ED2208::init(false)`），初始化序列无法唤醒深睡中的控制器。
3. 面板卡死后，所有 SPI 命令均被忽略，BUSY_N 持续拉低（数据手册：低电平=忙），每次 busy 等待烧满 20s 超时，所有刷新静默失效——ESP 本身正常启动（配网页可访问），屏幕永远停留在最后一次成功渲染的画面。

旁证：M5Stack 出厂固件（M5PaperColor-UserDemo）从不调用 `M5.Display.sleep()`，且在 `M5.begin` 后显式通过 M5PM1 GPIO0（PY_EPD_EN）管理墨水屏供电；M5GFX 源码中对 Paper 系列注释明确"EPD 处于 DeepSleep 时必须做 RST 控制"。

## 修复

- `src/app/app_runtime.cpp`
  - 新增 `resetEpdController()`：在 `M5.begin` 之前脉冲 RES#（GPIO12，低电平有效），按 ED2208 数据手册要求以 HWRESET 退出深睡——串口日志证实面板深睡后 BUSY_N 持续拉低，每次 busy 等待烧满 20s 超时，且 PM1 I2C 写入 NACK 使供电循环方案无法执行，HWRESET 是唯一可靠路径。
  - 新增 `powerCycleEpd()`：每次启动通过 M5PM1 GPIO0 对墨水屏断电 100ms → 上电 100ms → `M5.Display.wakeup()` 重发初始化序列，作为 HWRESET 之外的二次恢复手段（PM1 不可用时退化为仅重发初始化序列）。
  - 新增 `disableEpdPower()`：深度睡眠前等待刷新完成后直接断电面板，不再发送 `DEEP_SLEEP` 命令。
  - `appSetup()` 将 `initRgbLed()` 提前到墨水屏供电控制之前；禁用板载音频（`internal_spk`/`internal_mic`），避免 M5.begin 在共享 I2C 总线上探测未供电的 ES8311/ES7210 产生 i2c write NACK。
  - `prepareEpdAfterWakeup()` 冷启动白刷改为连续两次（`kEpdColdBootClearPasses = 2`）：面板恢复后首刷仍残留旧画面（淡灰色）叠加在新画面上的物理残影（image retention）——旧画面是早期固件按 Figma 设计占位日期（2026-01-21）渲染的，面板卡死期间长时间静止导致粒子烧入；后续每次唤醒的全量刷新会继续自然消退，无需进一步处理。
  - 保留并整理 `EPDDBG` 诊断日志（board 识别、busy 电平、复位/供电时序）。
- 测试：更新 `test_app_runtime`（睡眠路径不再发送面板 sleep 命令、断电时序断言、启动供电循环断言、RES# 复位脉冲断言），fake M5PM1/Arduino 补充 `pinMode`/`digitalWrite` 记录与常量。

## 关键证据

- ED2208 数据手册（Deep Sleep 章节）：*"To Exit Deep Sleep mode, User required to send HWRESET to the driver."*
- ED2208 数据手册（R12H 章节）：*"BUSY_N will become '0' [during refresh]. After the refresh process is finished, BUSY_N will become '1'."*
- 串口日志：`board=28 gfxBoard=28 busy=0`，每次 `M5.Display.wakeup()` 耗时恰好 40s（两次 20s 的 busy 超时），Power.begin 阶段 16 次 `[LGFX] i2c write error : ack wait`。

## 验证

- `pio test -e native`：177 通过。
- `pio run -e m5stack-papercolor`：构建通过。
